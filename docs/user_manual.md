## 1. 软件概述与纯净独立环境
本软件专为高安全等级嵌入式 C 语言（如车载 ECU、工业 PLC、航空航天航电设备等）研发与测试场景打造，全面集成了**静态代码质量分析**、**代码度量统计 (LOC/语句数/分支数/注释率/MCDC数)**、**函数独立路径提取与图元/源码联动着色探索**、**静态堆栈与二进制最大调用栈分析**、**基于 Qt 原生图元的代码拓扑可视化**、**语句/分支/函数覆盖率度量插桩**、**Python 激励向量注入**、**原生 Word (.docx) / 矢量 PDF 综合报告导出**以及**全生命周期运行日志审计**于一体。

### 1.1 纯净桌面 GUI 无黑框启动与 QPainter 启动加载画面
- **完全消除黑框控制台**：软件启动器和主程序均严格配置为 Windows 原生 GUI 子系统，运行时绝无 cmd.exe 黑框闪烁或停留，双击即直接呈现现代高精度图形界面。
- **高科技质感实时绘制启动画面 (Splash Screen)**：采用 `QPainter` 纯代码实时抗锯齿绘制深色科技风启动画面，展示动态渐变芯片徽标、多阶段加载提示与柔和进度条，在高 DPI 屏幕下呈现极致清晰的视觉效果。

### 1.2 启动界面自定义配置 (`config/app_config.ini`)
为了满足企业用户与不同团队对于产品品牌与加载时长的个性化需求，启动画面的核心要素均解耦至外部配置文件：
- **配置文件位置：** `config/app_config.ini`。
- **支持配置项：**
  - `[Product]`：产品主标题、副标题、版本徽章文本（如 `v2.6.0 专业版`）、底部架构声明；
  - `[SplashScreen] / MinDisplayTimeMs`：启动界面最少停留展示时长（毫秒，默认 2500ms），进度条平滑递增，告别闪退即逝的糟糕体验；
  - `Card1_Title / Desc / Color`、`Card2_*`、`Card3_*`：中间 3 张核心特性芯片卡片的标题、副标题与指示色标。

### 1.3 独立纯净程序目录 (`bin/`)
为了防止用户在数十个动态链接库（`.dll`）中找不到主程序，本软件采用了独立启动器隔离架构：
- **可执行程序独立目录：** 工程根目录下的 `bin/` 文件夹。
  - `bin/coverage_gui.exe`：图形化桌面端独立可执行程序（双击直接启动 GUI）。
  - `bin/coverage_cli.exe`：命令行无头分析工具。
- 目录内仅保留核心程序与必要环境，界面清爽，开箱即用。

### 1.4 系统外观明暗模式自动检测与主题自适应
- **操作系统外观自动感知**：软件启动时自动读取 Windows 系统的明暗外观主题配置。
  - 当操作系统处于**浅色模式**时，软件默认自动启用 **「现代清新白」** 主题；
  - 当操作系统处于**深色模式**时，软件默认自动启用 **「深色科技风」** 主题。
- **全局控件无缝自适应**：全面审计消除浅色模式下的深色方框或深色模式下的浅色底纹，全局按钮点击时已彻底消除外围白色焦点框线，视觉一致协调。
- **随时手动切换**：通过菜单栏 `设置 (&T) -> 界面风格主题 (Theme)`，用户可随时在 4 种现代主题（深色科技风、现代清新白、Solarized 暗夜、Monokai Pro）之间无缝切换。

### 1.5 内置独立便携 Python 与纯原生分析引擎 (零外部 exe 依赖)
- **内置绿色便携 Python 环境**：软件在 `bin/python/` 及 `tools/python/` 中内置了完整免安装的独立 Python 环境，用户执行测试脚本、生成激励向量或运行模糊测试时，系统自动优先调度内置 Python，**彻底免除用户自行下载或配置 Python 环境变量的繁琐步骤**。
- **纯内置原生二进制与堆栈解析引擎**：核心采用纯 C++ 实现，直接在内存中高效解析 ELF (32/64-bit) 与 Windows PE/COFF 二进制文件结构，自主解码机器码指令，**零第三方外部命令行工具 (.exe) 依赖**，运行更加轻量、安全与高效。

## 3. 规范目录隔离的项目管理与工程资源树

### 3.1 严格规范的项目目录隔离结构
为了防止不同工程的文件混杂导致编译与分析混乱，本软件强制遵循工业级目录隔离架构：
每个项目必须位于独立的同名项目文件夹下，并拥有专属且隔离的子目录结构：
```text
<ProjectName>/
├── <ProjectName>.covproj          # 核心工程元数据配置文件
├── Source/                        # 专属嵌入式 C/C++ 源码实现文件 (*.c, *.cpp)
├── Header/                        # 专属嵌入式头文件 (*.h)
├── Script/                        # 专属 Python 激励测试与注入脚本 (*.py)
└── Report/                        # 专属导出的质量与覆盖分析报告文件 (*.html, *.docx, *.pdf, *.json)
```
- 新建工程时，系统将自动创建上述 4 大子文件夹并将工程文件置于同级根目录；
- 打开工程时，不同项目之间的文件严格隔离，互不干扰。

### 3.2 工程管理中心 (`ProjectHubDialog`)
通过快捷键 `Ctrl+P` 或菜单 **「工程 (&P) -> 工程管理中心...」** 呼出：
- **➕ 创建新工程**：表单化配置工程名称、磁盘根目录、目标芯片架构（ARM Cortex-M/R, RISC-V, AutoSAR 等）与工程描述，一键生成标准隔离目录结构；
- **📂 打开已有工程**：浏览本地 `.covproj`，实时解析并高保真预览工程包含的源码数量、脚本数量与最后修改时间；
- **🕒 最近打开的历史工程**：持久化管理历史工程，支持双击快速载入。

### 3.3 专属矢量文件图标体系
左侧项目资源结构树全面摒弃“全部以文件夹图标呈现”的问题，引入专属高精度 SVG 矢量图标：
- 📦 **工程根节点**：使用专用的工程立方体图标 (`project.svg`)；
- 📁 **分类目录**：使用规范的目录图标 (`folder.svg`)；
- 📄 **C 源文件 (`*.c`, *.cpp)**：使用天蓝色专属图标 (`c_file.svg`)；
- 📄 **C 头文件 (`*.h`)**：使用浅紫色专属图标 (`h_file.svg`)；
- 🐍 **Python 激励脚本 (`*.py`)**：使用黄绿相间的 Python 专用图标 (`py_file.svg`)；
- 📊 **分析报告 (`*.html`, `*.pdf`, `*.docx`)**：使用醒目的报告专属图标 (`html_file.svg`)。

### 3.4 规范分类与分类节点右键屏蔽
左侧工程资源树统一规范为 4 大核心分类节点：
1. **源文件**
2. **头文件**
3. **脚本文件**
4. **报告文件**

- **屏蔽分类节点的右键干扰**：用户在「源文件」、「头文件」、「脚本文件」、「报告文件」等分类节点上右键时，系统自动屏蔽无效弹窗，符合专业工业软件的交互习惯。

### 3.5 全右键上下文菜单集成
原底部的「添加文件」、「添加目录」、「移除选中」三个独立占用界面的按钮已**全部精简整合至右键上下文菜单中**：
- **在空白处或工程根节点右键：**
  - ➕ **添加源文件/脚本到工程...**：多选批量添加源文件；
  - 📁 **导入源码目录到工程...**：递归扫描并导入工程源码目录；
  - ⚙️ **工程属性与配置 (Hub)...**：配置芯片架构与工程描述；
  - 💾 **保存当前工程**：持久化工程配置至 `.covproj`。
- **在具体文件节点右键：**
  - 源文件：`在多标签编辑器中打开`、`⚡ 执行静态分析与路径探索`、`执行源码探针插桩 (F6)`；
  - 脚本文件：`▶ 执行此 Python 激励脚本`、`在 Python 激励工作台中打开编辑`；
  - 报告文件：`在内置全貌预览框中查看`；
  - ➕ **添加文件到工程...** / 📁 **导入目录到工程...**；
  - 🗑️ **从当前工程移除选中文件**：一键安全移出工程清单。

## 4. Visual Studio 风格自由停靠工作区与「视图」菜单

### 4.1 全组件自由停靠、浮动分屏与 Tab 合并
系统借鉴了现代专业集成开发环境（如 Microsoft Visual Studio / CLion）的高级窗口停靠管理体系：
- **自由拖拽移动**：拖动任意窗口标题栏将其停靠在左、右、上、下任意方位或四角；
- **独立浮动分屏**：将任意面板拖出主窗体成为独立桌面浮动窗口（支持多显示器分屏作业）；
- **自由标签页合并**：将任意窗口拖拽覆盖在另一个窗口上，自动合并为紧凑的 Tab 选项卡组；
- **智能工作区联动**：当进入「静态分析与路径探索」时，系统自动隐藏右侧覆盖度量与激励注入栏，为复杂分支拓扑和代码对比留出完整的横向可视宽度；切换回代码编辑或运行激励时自动恢复。

### 4.2 底部缺陷列表与系统运行日志的原生统一集成
根据实际工程排错需求，静态分析发现的代码潜在缺陷与后端的实时运行控制台日志紧密相关。系统将两者**默认且原生放置在同一块底部停靠组件内**，通过子选项卡进行无缝切换：
- **选项卡 1: 静态缺陷列表**：展示规则编号、文件名、行号、严重等级与修复建议；
- **选项卡 2: 实时运行日志**：彩色终端格式输出引擎分析耗时、插桩探针注入统计与 Python 激励回显。

### 4.3 标签页与停靠视窗右键关闭体系
- **多源码文件选项卡右键事件**：
  - **关闭当前页 (Close Current)**：关闭当前选中的代码文件；
  - **关闭除当前外所有页 (Close Others)**：仅保留当前正在审阅的文件；
  - **关闭所有页面 (Close All)**：清空所有打开的代码视窗；
  - **复制完整文件路径 (Copy Path)**：一键复制绝对路径到剪贴板。
- **中央停靠标签栏 (Dock TabBar) 右键事件**：
  - 右键点击「欢迎向导」、「源代码编辑器」、「静态分析与路径探索」、「调用拓扑图」、「静态堆栈分析」标签栏任意标签，即可一键执行关闭当前页、关闭其他页或关闭所有页面。

### 4.4 「视图 (&V)」菜单状态勾选与一键恢复默认布局
菜单栏新增了专用的「视图 (&V)」菜单：
- **可视状态勾选标记**：每个窗口选项前均带有即时选中的复选勾（Checkmark），用户可一眼看清当前窗口是否处于打开状态；
- **欢迎向导独立管理**：欢迎向导不作为工程常驻视窗混杂在视图菜单中；
- **「🔄 恢复默认窗口布局」**：一键将所有浮动、移动或关闭的窗口瞬间还原为官方初始经典 Visual Studio 黄金比例排版！

### 4.5 紧凑精致的主控制工具栏
主控制工具栏按钮间距进行了紧凑排版优化：
- 统一设定紧凑的工具栏内边距与按钮间距（`spacing: 3px; padding: 2px 4px;`）；
- 图标规格精致标准（18x18），间距舒适和谐，大幅减少纵向屏幕占用，提升代码可视面积。

## 5. 静态分析与控制流路径探索工作台
在主窗口点击或切换至 `静态分析与路径探索` 窗口，即可进入专为嵌入式架构师与测试工程师设计的深层代码质量与控制流分析平台。该工作台采用了**双选项卡（TabWidget）设计**：

### 5.1 选项卡 1:「函数度量总览」
全面展示当前源文件全局与函数级别的综合质量度量指标：
1. **顶部六大 KPI 度量看板**：
   - **语句数 (Statements)**：准确统计真实有效 C 执行语句数量（排除注释与空行）。
   - **分支数 (Branches)**：统计 `if`、`else if`、`switch/case`、三元运算符等条件决策分支总量。
   - **注释率 (Comment Ratio)**：以百分比呈现代码规范注释率，辅助把控嵌入式工程文档化标准。
   - **MC/DC 判定与条件数**：统计复合逻辑表达式中的判定点（Decisions）与原子条件（Conditions）数量，为汽车电子 ISO 26262 ASIL-D 级 MC/DC 覆盖分析提供基准。
   - **最高圈复杂度 (McCabe)**：标出当前文件中圈复杂度最高的值，辅助定位重构瓶颈。
   - **缺陷违规数 (Issues)**：标出静态分析检测到的安全隐患与 MISRA 规范违规总量。
2. **全函数结构度量表格**：
   - 表格严格呈现以下 **6 个关键信息列**：
     1. **函数序号** (Index)
     2. **函数名称** (Function Name)
     3. **函数路径** (File Path / Scope)
     4. **语句数** (Statements)
     5. **分支数** (Branches)
     6. **MCDC数** (MC/DC Conditions)
   - **双击交互跳转**：在表格中双击任意一行函数，系统将**自动切换至「函数控制流与路径探索」选项卡**，并同步选定该函数展开其控制流图与路径列表。

### 5.2 选项卡 2:「函数控制流与路径探索」
采用高效的三栏式并列对比交互架构：
1. **左栏：函数选择与独立基路径 (Basis Paths) 列表**：
   - 顶部提供函数下拉选择器，快速切换当前文件中的不同函数；
   - 下方自动解析并展示该函数在数学上的全部**线性独立基路径**（路径序号、条件判定说明及覆盖代码行数）；

## 6. 静态堆栈与二进制调用深度分析器 (Static Stack Analyzer)

### 6.1 工具定位与安全标准背景
在 **ISO 26262 ASIL-D**（汽车电子）与 **DO-178C Level A**（机载航电）标准中，嵌入式系统运行期发生堆栈溢出（Stack Overflow）是引发不可控故障的重大隐患。静态堆栈分析工具通过完全静态、非侵入的方式，分析编译生成的二进制可执行程序与目标文件，求解程序在最坏情况下的**最大调用栈深度峰值 (Worst-Case Peak Stack Depth)** 与完整调用链路，并检测直接或间接递归风险。

### 6.2 编译前置建议与 GCC `-fstack-usage` (.su) 机制
- **推荐编译配置 (GCC / Clang)**：
  在编译嵌入式源码时，推荐开启 `-fstack-usage` 编译选项：
  ```bash
  gcc -O2 -fstack-usage -g -c main.c -o main.o
  ```
  编译器将为每个源文件生成同名 `.su` 文件，记录每个函数的精确局部帧字节大小及类型（`static` 确定性栈 / `dynamic` 动态分配栈）。
- **无 .su 文件时的纯原生指令级推导 (Zero EXE)**：
  若工程未生成 `.su` 文件，软件将自动启用纯内置的 C++ 机器码指令解码引擎，智能扫描目标二进制中的 `sub esp/rsp`、`push`、`stp`、`str` 等入栈分配汇编指令，配合 AST 源码调用拓扑，精确推导函数自身局部栈用量，全程无需任何外部进程调用。

### 6.3 目标二进制加载与自动检索
- 打开项目后，系统会自动在工程目录及其 `bin/`、`build/`、`Source/` 子目录下智能检索匹配的可执行文件（`*.exe`, `*.elf`, `*.axf`, `*.o`, `*.obj`）；
- 用户亦可在堆栈分析工作台顶部点击「浏览...」手动选取任意二进制文件与对应的 `.su` 文件；
- 点击 **「⚡ 执行静态堆栈分析」** 即可瞬间完成全量反汇编、符号解析、全局调用拓扑构建与 DFS 最坏情况路径求解。

### 6.4 8 列全量函数栈用量与 MISRA 17.2 递归检测
主列表以直观表格呈现全部函数指标：
1. **序号** (Index)
2. **函数名称** (Function Name)
3. **所在源码文件** (Source File) —— 自动结合 DWARF 调试符号与 AST 源码映射
4. **行号** (Line Number)
5. **自身栈大小 (B)** (Local Stack Size in Bytes)
6. **最大调用栈 (B)** (Max Call Stack Depth in Bytes)
7. **调用类型** (`static` 确定性固定栈 / `dynamic` 动态栈 / `indirect` 间接调用)
8. **递归风险** (MISRA 17.2 规范遵循状态，标记“无递归”或高亮警示“直接递归/间接递归”)

点击表格中任意一行函数，右下方窗口立即同步高亮显示该函数的**反汇编代码与入栈分配指令片段**。

### 6.5 最坏情况最大调用栈 (Worst-Case Peak Stack) DFS 求解
- 系统采用深度优先搜索 (DFS) 有向无环图 (DAG) 算法，从所有根节点（如 `main`、中断 ISR 入口）开始遍历所有可能的子函数调用路径；
- 自动计算并输出**全局最大调用栈消耗峰值**、**根节点函数**、**函数调用总数**及**最坏情况完整调用链**（如 `main -> motor_controller_update -> motor_check_safety`）。

### 6.6 Graphviz 矢量调用拓扑图高亮呈现
在右侧面板提供双选项卡：
- **选项卡 1【调用链层级树】**：树形节点展开查看，点击任一节点可直接定位对应函数；
- **选项卡 2【调用拓扑图 (Graphviz)】**：利用 Graphviz 矢量引擎绘制由根节点通往最深子函数的完整调用拓扑图；
  - 连线标注每次调用的栈增量权重（如 `+40B`）；
  - 最坏情况调用链上的关键节点边框以**翠绿加粗 (#10b981)** 突出显示；
  - 支持画布平滑无级缩放与拖拽查看。

### 6.7 堆栈分析报告导出
点击顶部 **「导出报告」** 按钮，可将完整的静态堆栈分析数据、KPI 看板、全函数度量明细与最坏情况调用链导出为**格式化纯文本 (.txt)**、**Markdown (.md)** 或 **JSON (.json)** 格式，便于直接纳入功能安全设计验证交付文档。

## 7. MISRA-C 与嵌入式代码安全规范检测
在底部「静态缺陷列表」面板查阅所有检测出的问题。规则描述与修复建议已实现**多语言自动切换**（随软件语言在中文与英文间无缝切换）。

### 7.1 嵌入式关键安全规则集
- **MISRA C:2012 Rule 21.3**：在安全关键嵌入式系统中严禁使用动态内存分配函数（`malloc` / `calloc` / `free`），改用确定性静态预分配内存。
- **MISRA C:2012 Rule 17.2**：禁止函数直接或间接递归调用，防止不可预期的栈溢出崩溃。
- **MISRA C:2012 Rule 16.4**：`switch` 语句必须显式声明包含 `default` 分支，防止状态机悬空。
- **MISRA C:2012 Rule 15.7**：`if ... else if` 结构末尾必须包含终止性的 `else` 分支。
- **MISRA C:2012 Rule 12.1**：禁止使用 `==` 或 `!=` 直接对比浮点数，防范浮点精度误差引发死循环。
- **EMB-VOLATILE-01**：直接访问硬件外设或内存映射寄存器时必须使用 `volatile` 限定符修饰，防止被编译器过度优化。
- **METRIC-CYCLOMATIC-COMPLEXITY**：圈复杂度超标警示（阈值 > 10），提示拆分复杂函数。

### 7.2 缺陷列表与代码编辑器行号联动
在底部缺陷列表中点击或双击任意一条缺陷违规记录，系统将**自动在多文件编辑器中打开对应源文件，并瞬时跳转并高亮定位至违规代码行号**。

## 13. 车规级完备嵌入式 C 示例工程详解
软件在 `examples/` 目录下提供两套符合现代嵌入式隔离目录规范的真实工业级示例工程：

### 13.1 车载电机驱动工程 (Motor Controller)
- **目录位置：** `examples/motor_controller/`
  - `motor_controller.covproj`：工程元数据定义文件；
  - `motor_controller.exe`、`motor_controller.su`：已预编译完成的目标程序与栈度量文件，可直接用于体验静态堆栈分析；
  - `Source/`：`main_embedded.c` (10kHz 中断 ISR、100Hz 状态机周期主控任务)、`motor_controller.c` (双闭环抗饱和 PID 控制算法)、`bsp_pwm.c` (三相 PWM 互补驱动与死区时间校准)、`safety_monitor.c` (ISO 26262 ASIL-B 功能安全监控)、`can_comm.c` (车载 CAN 协议栈与 CRC8 查表)；
  - `Header/`：`motor_types.h`、`motor_controller.h`、`bsp_pwm.h`、`safety_monitor.h`、`can_comm.h`、`coverage_runtime.h`；
  - `Script/`：`can_frame_injector.py` (CAN 报文激励)、`boundary_fuzzer.py` (极限边界与模糊测试)。

### 13.2 姿态多传感器融合工程 (Sensor Fusion)
- **目录位置：** `examples/sensor_fusion/`
  - `sensor_fusion.covproj`：工程元数据定义文件；
  - `sensor_fusion.o`、`sensor_fusion.su`：已编译的目标对象文件与栈度量文件；
  - `Source/sensor_fusion.c`：六轴陀螺仪与加速度计姿态解算互补滤波算法；
  - `Header/sensor_fusion.h`：传感器接口定义；
  - `Script/sensor_waveform_injector.py`：正弦波振动激励注入套件。

## 15. 命令行工具 (CLI) 使用说明
在自动化测试、CI/CD 持续集成或夜间构建流程中，可通过独立的 `bin/coverage_cli.exe` 进行无头快速分析：

```powershell
# 1. 针对指定嵌入式 C 源码执行静态质量检测与圈复杂度评估
.\bin\coverage_cli.exe -f examples\motor_controller\Source\motor_controller.c --analyze

# 2. 直接导出原生 Word (.docx) 质量报告
.\bin\coverage_cli.exe -f examples\motor_controller\Source\motor_controller.c -w reports\motor_report.docx

# 3. 导出独立 HTML 网页质量报告
.\bin\coverage_cli.exe -f examples\motor_controller\Source\motor_controller.c -m reports\motor_report.html

# 4. 导出 JSON 结构化数据
.\bin\coverage_cli.exe -f examples\motor_controller\Source\motor_controller.c -r reports\report.json

# 5. 执行源码探针插桩并输出到指定路径
.\bin\coverage_cli.exe -f examples\motor_controller\Source\motor_controller.c --instrument -o build\motor_controller.inst.c
```
